Структуры данных: что выбрать под задачу

Продолжение урока про O-нотацию. Там мы выяснили, как считать стоимость операций; здесь — какие структуры какую стоимость дают и когда какую брать. В тесте ты угадала вопросы про очередь и коллизии: ответила верно, но без опоры.

Структура данных — это компромисс

Идеальной структуры не бывает. Каждая делает быстрыми одни операции ценой других. Выбор всегда сводится к вопросу: что я буду делать с этими данными чаще всего?

Читать по индексу? Искать по значению? Вставлять в середину? Проверять принадлежность? Ответ на этот вопрос и определяет структуру, а вовсе не привычка писать везде массив.

Обрати внимание на строку «вставка в начало». В JS это arr.unshift() и arr.shift(): обе операции сдвигают все оставшиеся элементы, то есть стоят O(n). Очередь, сделанная на массиве через shift(), на больших объёмах работает квадратично — классическая незаметная просадка.

Стек и очередь: одно правило доступа

Это не столько хранилища, сколько дисциплины доступа. Обе разрешают трогать данные только с краю — и именно поэтому обе работают за O(1).

Стек — LIFO, last in, first out

Кладём и забираем с одного конца, как стопку тарелок. Последний вошёл — первым вышел.

const stack = [];
stack.push('a');  stack.push('b');
stack.pop();      // 'b' — последний добавленный

Где встречается: стек вызовов функций, история для undo, кнопка «назад» в браузере, обход дерева в глубину, проверка парности скобок.

Очередь — FIFO, first in, first out

Кладём в один конец, забираем с другого, как очередь в кассу. Первый вошёл — первым вышел.

const queue = [];
queue.push('a');  queue.push('b');
queue.shift();    // 'a' — первый добавленный (но это O(n)!)

Где встречается: очередь макрозадач в event loop из прошлого урока, обработка запросов сервером, очередь загрузок, обход дерева в ширину.

Мнемоника. Стек — стопка тарелок: моешь последнюю положенную. Очередь — касса: обслуживают того, кто пришёл раньше. Отсюда же и разница в поведении event loop и стека вызовов.

Хеш-таблица: поиск за O(1)

Самая полезная структура во фронтенде и самая недооценённая. В JS это Object, Map и Set.

Идея: берём ключ, прогоняем через хеш-функцию — она превращает ключ любого вида в число. Это число используем как индекс в массиве ячеек. Получается, что поиск по ключу сводится к доступу по индексу, а он, как мы знаем, O(1).

hash("email") → 4172 → ячейка 4172 % 16 = 8
Ищем "email" → снова считаем хеш → сразу идём в ячейку 8

Коллизии

Коллизия — это когда два разных ключа дают один и тот же хеш и претендуют на одну ячейку. Это не поломка, а неизбежность: ключей бесконечно много, а ячеек конечное число.

Решают обычно цепочками: в ячейке лежит не одно значение, а список всех попавших туда пар «ключ-значение». При поиске проходят по короткому списку и сравнивают ключи честно.

Отсюда и оговорка «O(1) в среднем»: если хеш-функция плохая и всё свалилось в одну ячейку, поиск вырождается в O(n). На практике встроенные реализации это надёжно решают.

Практическое правило: если это структура записи с известными полями — бери объект. Если это словарь, который наполняется в рантайме и часто меняется — бери Map. Если нужна только принадлежность множеству — бери Set.

Три приёма, которые пригодятся завтра

Убрать дубликаты

const unique = [...new Set(items)];   // O(n)

Посчитать частоты

const counts = new Map();
for (const word of words) {
  counts.set(word, (counts.get(word) ?? 0) + 1);
}
// O(n), а не O(n²) как через counts.filter(...)

Соединить два списка по id

// плохо: O(n × m) — find внутри map
const rows = users.map(u => ({ ...u, order: orders.find(o => o.userId === u.id) }));

// хорошо: O(n + m) — индекс строится один раз
const byUser = new Map(orders.map(o => [o.userId, o]));
const rows = users.map(u => ({ ...u, order: byUser.get(u.id) }));

Это тот же приём, что и Set вместо includes из первого урока: заменяем повторный поиск на однократное построение индекса. Узнаваемый признак — вызов find, includes или filter внутри другого перебора.

Что уносим с собой. Стек — LIFO, очередь — FIFO, обе дают O(1) за счёт работы только с краем. Хеш-таблица меняет память на скорость поиска. Коллизия — совпадение хешей у разных ключей, решается цепочками. shift() и unshift() в JS стоят O(n). Поиск внутри цикла — сигнал построить Map или Set.
