Динамическое программирование и мемоизация

Закрывает провал продвинутого теста: во сколько раз мемоизация ускоряет рекурсию чисел Фибоначчи. Динамическое программирование звучит пугающе, а идея простая: не решай одну и ту же подзадачу дважды. Это лекарство от экспоненциальной сложности, и оно встречается в реальном коде чаще, чем кажется, — от кэшей до поиска различий между файлами.

Почему наивная рекурсия тонет

Числа Фибоначчи: F(n) = F(n−1) + F(n−2). Прямолинейная реализация:

function fib(n) {
  if (n < 2) return n;
  return fib(n - 1) + fib(n - 2);
}

Работает, но fib(40) уже заметно медлит. Каждый вызов порождает два новых, и дерево вызовов растёт вдвое на каждом уровне — сложность O(2ⁿ). Причина не в количестве разных задач (их всего n), а в том, что одни и те же считаются заново и заново: fib(3) внутри fib(40) вычисляется миллионы раз.

fib(5)
├─ fib(4)
│  ├─ fib(3)  ← считается
│  └─ fib(2)
└─ fib(3)     ← и снова
   ├─ fib(2)
   └─ fib(1)

Мемоизация: запомнить готовое

Мемоизация — кэшировать результат по аргументам. Когда подзадача уже решена, берём ответ из памяти:

function fib(n, memo = new Map()) {
  if (n < 2) return n;
  if (memo.has(n)) return memo.get(n);
  const r = fib(n - 1, memo) + fib(n - 2, memo);
  memo.set(n, r);
  return r;
}

Теперь каждое fib(k) вычисляется один раз, остальные обращения — чтение из таблицы. Сложность падает с O(2ⁿ) до O(n) по времени и O(n) по памяти. Разница чудовищная: 40-е число — около миллиарда операций против сорока.

Когда мемоизация применима. Функция должна быть чистой — результат зависит только от аргументов, без побочных эффектов, — и подзадачи должны повторяться. Если повторов нет (как в сортировке слиянием), кэш бесполезен и лишь ест память.

Снизу вверх: таблица

Вторая форма динамического программирования — не рекурсия сверху с кэшем, а итеративное заполнение таблицы снизу вверх: от самых маленьких подзадач к большой. Для Фибоначчи достаточно двух последних значений:

function fib(n) {
  let a = 0, b = 1;
  for (let i = 0; i < n; i++) [a, b] = [b, a + b];
  return a;
}

Время O(n), память O(1), и нет риска переполнения стека вызовов на больших n. Сверху вниз (мемоизация) проще писать — берёшь готовую рекурсию; снизу вверх (таблица) обычно быстрее и экономнее по памяти.

Когда задача «динамическая»

Два признака:

  1. Перекрывающиеся подзадачи — одни и те же подзадачи встречаются многократно.
  2. Оптимальная подструктура — оптимальное решение целого складывается из оптимальных решений частей.

Классические примеры:

  • Задача о рюкзаке — набрать предметы максимальной ценности при ограничении по весу. Таблица «лучшая ценность для первых i предметов и вместимости w».
  • Размен монет — минимальное число монет на сумму. Жадный выбор «самой крупной» не всегда верен (монеты 1, 3, 4 и сумма 6: жадно 4+1+1, а оптимально 3+3), а таблица даёт точный ответ.
  • Наибольшая общая подпоследовательность и расстояние Левенштейна — основа diff и исправления опечаток.
  • Количество путей в сетке — ячейка равна сумме ячеек сверху и слева.

Как решать

  1. Сформулируй решение через меньшие подзадачи («ответ для n через n−1 и n−2»).
  2. Определи, какие параметры однозначно задают подзадачу (это ключ кэша или индексы таблицы).
  3. Реши рекурсивно, затем добавь кэш. Если нужна экономия памяти — переложи в таблицу.
Что уносим с собой. Наивная рекурсия Фибоначчи — O(2ⁿ), потому что одни и те же подзадачи считаются заново. Мемоизация кэширует ответы и опускает время до O(n). Таблица снизу вверх делает то же итеративно и порой с O(1) памяти. Признаки задачи — перекрывающиеся подзадачи и оптимальная подструктура; классика — рюкзак, размен монет, расстояние Левенштейна.
