Типы, приведение и тихие потери данных

Три ошибки в тесте были из одной семьи: typeof null, что вернёт a?.b?.c и что сделает JSON.stringify с undefined. Общее у них то, что язык не падает с ошибкой, а молча отдаёт не то, что ждёшь. Такие баги ищутся дольше всех.

Восемь типов и одна историческая ошибка

В JavaScript семь примитивов — number, string, boolean, null, undefined, bigint, symbol — и всё остальное: объекты, а вместе с ними массивы, функции, Date, Map.

Проверить тип позволяет typeof, и вот его полная таблица:

ВыражениеРезультатКомментарий
typeof 42"number"
typeof "a""string"
typeof true"boolean"
typeof undefined"undefined"
typeof null"object"баг языка
typeof []"object"массив — это объект
typeof {}"object"
typeof function(){}"function"единственное исключение
typeof NaN"number"«не число» имеет тип число

typeof null === "object" — не логика, а ошибка первой реализации 1995 года. Внутри значения помечались тегом, и у объектов тег был 000; null представлялся нулевым указателем, то есть тоже сплошными нулями. Исправить это уже нельзя: слишком много кода на такое поведение опирается.

Практический вывод — проверять на null нужно напрямую:

// не работает
if (typeof x === "object") { /* сюда попадёт и null */ }

// работает
if (x === null) { … }
if (x !== null && typeof x === "object") { /* настоящий объект */ }
Array.isArray(x)          // единственный честный способ отличить массив

null и undefined — разные вещи

undefined — «значения тут нет и никогда не задавали». Его отдаёт язык: необъявленное поле объекта, аргумент, который не передали, функция без return.

null — «здесь намеренно пусто». Его ставит программист.

Правило по умолчанию: null пишешь ты, undefined пишет язык. Смешивать их в собственных структурах данных не стоит — тогда проверка «пусто ли» превращается в гадание.

== против ===

=== сравнивает без приведения: разные типы — сразу false. == сначала приводит операнды к общему типу, и правила приведения довольно причудливы:

0 == "0"          // true   — строка стала числом
0 == ""           // true   — пустая строка стала нулём
0 == false        // true   — false стал нулём
"" == false       // true
null == undefined // true   — специальное правило
null == 0         // false  — а вот тут никакого приведения нет
NaN == NaN        // false  — NaN не равен ничему, включая себя
Правило. Всегда ===. Единственное осмысленное исключение — x == null: это компактная проверка «null или undefined» разом, и она безопасна, потому что ни с чем другим null нестрого не равен.

Отдельно про NaN: раз он не равен себе, сравнением его не поймать. Ловят функцией Number.isNaN(x). Глобальная isNaN(x) — другая: она сначала приводит аргумент к числу, поэтому isNaN("привет") даёт true, хотя строка — не NaN.

Ложные значения: их ровно шесть

false   0   ""   null   undefined   NaN

Всё остальное истинно. Из этого вытекают две регулярные ловушки:

Boolean("0")    // true  — непустая строка
Boolean([])     // true  — пустой массив истинен
Boolean({})     // true
[] == false     // true  — а вот при == приведение даёт другой ответ

Последняя строка выглядит как противоречие, но противоречия нет: if ([]) приводит массив к булеву значению по правилу «объект всегда истинен», а [] == false приводит обе стороны к числу — [] становится "", затем 0. Это ровно тот случай, ради которого == и не используют.

|| и ?? — разница в одной строчке

|| отдаёт правый операнд, если левый ложный. ?? — только если левый null или undefined.

const count = props.count || 10;   // передали 0 → получили 10, баг
const count = props.count ?? 10;   // передали 0 → получили 0

const name = props.name || "Гость"; // передали "" → "Гость"
const name = props.name ?? "Гость"; // передали "" → пустая строка

Значение по умолчанию почти всегда должно ставиться через ??: ноль, пустая строка и false — это данные, а не отсутствие данных. Исключение — когда пустую строку действительно хочется считать «не задано».

Опциональная цепочка ?.

a?.b означает: если a — null или undefined, вернуть undefined, иначе взять b. Ключевой момент: возвращается всегда undefined, даже если слева был null.

const a = null;
a?.b?.c    // undefined, НЕ null

Причина в том, что «свойства нет» язык всегда обозначает через undefined — ?. просто не делает исключения из этого правила.

Второй ключевой момент — короткое замыкание: как только слева оказалось пусто, остаток цепочки не вычисляется вообще.

user?.profile.avatar.url
// user есть, profile нет → TypeError:
// ?. защитил только один шаг, дальше идёт обычный доступ

user?.profile?.avatar?.url    // безопасно на каждом шаге

obj.method?.()      // вызов, только если метод существует
arr?.[0]            // индекс, только если массив существует
onChange?.(value)   // частый приём для необязательных колбэков
Чего ?. не делает. Он не защищает от пустого результата дальше по коду. const n = user?.name.length упадёт, если user есть, а name нет. И он не заменяет проверку данных: если undefined утекает в разметку, ты увидишь не ошибку, а пустое место — искать такое сложнее.

JSON.stringify молча теряет данные

JSON — формат беднее, чем объектная модель JavaScript. Всё, чему в нём нет соответствия, выбрасывается без единого предупреждения:

JSON.stringify({ a: undefined, b: 1 })   // '{"b":1}'   — ключа a просто нет
JSON.stringify({ f: () => 1, b: 1 })     // '{"b":1}'   — функции выброшены
JSON.stringify([1, undefined, 2])        // '[1,null,2]' — в массиве становится null
JSON.stringify({ d: new Date() })        // дата стала строкой
JSON.stringify({ n: NaN, i: Infinity })  // '{"n":null,"i":null}'
JSON.stringify(new Map([["a", 1]]))      // '{}'  — Map и Set пустеют
JSON.stringify({ big: 10n })             // TypeError — BigInt не сериализуется

Разница между объектом и массивом здесь не случайна. У объекта ключ можно просто не писать — структура останется валидной. В массиве позиции нумерованные, выкинуть элемент нельзя, не сдвинув остальные, поэтому дыру затыкают null.

Отсюда следствие для популярного приёма глубокого копирования JSON.parse(JSON.stringify(obj)): он работает только для данных, которые и так пришли из JSON. Дата после такого копирования станет строкой, Map опустеет, поля с undefined исчезнут, а циклическая ссылка бросит TypeError. Для честной копии есть structuredClone(obj).

Числа: одна ловушка, которую надо знать в лицо

0.1 + 0.2 === 0.3        // false
0.1 + 0.2                // 0.30000000000000004

Все числа в JavaScript — двоичные с плавающей точкой (IEEE 754). Дробь 0.1 в двоичной системе бесконечна ровно так же, как 1/3 в десятичной, поэтому хранится с округлением. Это не баг языка, так же ведут себя Python, Java и C.

Практика: деньги считают в копейках целыми числами, а сравнивают дроби через допуск — Math.abs(a - b) < 1e-9.

Что уносим с собой. typeof null === "object" — историческая ошибка, массив ловится только через Array.isArray. Сравнение — всегда ===, кроме идиомы x == null. Ложных значений шесть, "0" и [] в их число не входят. Значения по умолчанию — через ??, иначе ноль и пустая строка потеряются. ?. всегда возвращает undefined и защищает ровно тот шаг, где стоит. JSON.stringify выбрасывает undefined и функции, а в массиве заменяет их на null.
