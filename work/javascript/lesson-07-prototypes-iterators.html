JavaScript в глубину: прототипы, итераторы, генераторы и WeakMap

Закрывает провалы продвинутого теста: что возвращает функция-генератор, чем prototype отличается от __proto__ и чем WeakMap отличается от Map. Всё это — механизмы, на которых стоят классы, циклы for…of, spread и async-код. Знать их «изнутри» — значит понимать, почему язык ведёт себя именно так.

Прототипная цепочка

В JS у каждого объекта есть скрытая ссылка на другой объект — его прототип. Когда свойство не найдено в самом объекте, поиск идёт вверх по цепочке прототипов, пока не дойдёт до null. Так работает наследование: методы массива лежат не в каждом массиве, а один раз в Array.prototype.

const animal = { eats: true };
const rabbit = { jumps: true };
Object.setPrototypeOf(rabbit, animal);

rabbit.jumps;   // true — своё
rabbit.eats;    // true — найдено у прототипа

Путаницу вносят два похожих имени:

ИмяЧто это
__proto__ (лучше Object.getPrototypeOf(obj))ссылка у самого объекта на его прототип — то, по чему идёт поиск
prototypeсвойство функции-конструктора: объект, который станет прототипом всех, созданных через new
function Dog() {}
Dog.prototype.bark = function () { return "гав"; };
const d = new Dog();

Object.getPrototypeOf(d) === Dog.prototype;   // true

class — синтаксический сахар над этим же механизмом: методы класса ложатся в Class.prototype, а extends связывает цепочки.

Итераторы и протокол итерации

Цикл for…of, spread [...x], деструктуризация работают с любым итерируемым объектом. Это объект с методом [Symbol.iterator](), возвращающим итератор — объект с методом next(), который отдаёт { value, done }.

const it = [10, 20][Symbol.iterator]();
it.next();   // { value: 10, done: false }
it.next();   // { value: 20, done: false }
it.next();   // { value: undefined, done: true }

Итерируемы массивы, строки, Map, Set. Обычный объект — нет: for (x of {}) выбросит ошибку.

Генераторы

Функция со звёздочкой function* — генератор. Главное свойство: вызов не выполняет тело, а возвращает объект-итератор. Тело стартует и идёт до первого yield только при вызове next(), затем ставится на паузу.

function* count() {
  console.log("старт");
  yield 1;
  yield 2;
}
const it = count();   // ничего не напечатано
it.next();            // «старт», { value: 1, done: false }

Это ленивые вычисления: бесконечную последовательность можно описать и брать нужное число элементов. Генераторы удобны для пагинации, обхода деревьев, потоков данных. Механика «остановиться и продолжить» лежит и в основе async/await, который исторически строился поверх генераторов.

Weak-коллекции и сборка мусора

Map держит ключи сильными ссылками: пока объект лежит в Map как ключ, сборщик мусора его не уберёт, даже если больше нигде объект не используется. Это классическая утечка памяти при кэшировании данных «по объекту».

WeakMap отличается двумя вещами:

  • ключами могут быть только объекты (и несобранные символы);
  • ссылка на ключ слабая: если на объект больше ничто не ссылается, он собирается, и запись исчезает.
const meta = new WeakMap();
function track(el) { meta.set(el, { clicks: 0 }); }
// когда el удалят из DOM и забудут, запись сама исчезнет

Платой служит то, что WeakMap нельзя перебрать и узнать размер: содержимое зависит от сборщика мусора и непредсказуемо. Применение — приватные данные объектов и кэши, привязанные к жизни ключа.

WeakSet и WeakRef. Те же идеи: WeakSet — множество слабых объектов, WeakRef — слабая ссылка, через которую можно получить объект, если он ещё жив. Рассчитывать на момент сборки нельзя.

Что уносим с собой. Свойство ищется по цепочке прототипов; __proto__ — ссылка объекта на прототип, а prototype — свойство конструктора, задающее его для экземпляров. for…of работает с объектами, у которых есть [Symbol.iterator]. Вызов генератора возвращает итератор и не запускает тело — оно идёт по next(). WeakMap держит объекты-ключи слабо и не мешает сборке мусора.
