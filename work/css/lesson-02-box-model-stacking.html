Box model, position и контекст наложения

Два вопроса теста — про box-sizing: border-box (#30) и про z-index (#33) — ты отметила как угаданные. Это ровно те две темы, из которых растут «почему блок шире, чем я задала» и «почему z-index: 9999 не помогает». Обе разбираются до конца и после этого не возвращаются.

Коробка состоит из четырёх слоёв

Любой элемент в CSS — прямоугольник из вложенных областей:

┌─────────── margin (снаружи, прозрачный) ───────────┐
│  ┌───────── border ─────────────────────────────┐  │
│  │  ┌────── padding ────────────────────────┐   │  │
│  │  │  ┌─── content ───┐                    │   │  │
│  │  │  │   текст       │                    │   │  │
│  │  │  └───────────────┘                    │   │  │
│  │  └───────────────────────────────────────┘   │  │
│  └──────────────────────────────────────────────┘  │
└────────────────────────────────────────────────────┘

Весь вопрос в том, что именно считает свойство width. Ответ зависит от box-sizing:

content-box (по умолчанию)border-box
width задаёттолько ширину контентаконтент + padding + border
Занимаемое местоwidth + padding + borderровно width
width: 200px; padding: 20px; border: 5px solid;

content-box:  200 + 20·2 + 5·2 = 250px на экране
border-box:   ровно 200px; контенту достаётся 200 − 40 − 10 = 150px

Margin не входит никогда — ни в тот, ни в другой режим. Он снаружи коробки и в её ширине не участвует.

Именно поэтому почти любой проект начинается со строчки:

*, *::before, *::after { box-sizing: border-box; }

Смысл её в том, что «ширина 50%» начинает означать ровно половину, независимо от того, добавят элементу рамку или отступы. Считать в уме больше не нужно.

Схлопывание отступов. Вертикальные margin соседних блоков не складываются, а сливаются: 20px снизу и 30px сверху дадут промежуток 30px, а не 50px. Схлопываются и margin родителя с margin первого ребёнка, если между ними нет border, padding или переполнения. Горизонтальные margin не схлопываются никогда, во флексбоксе и гриде — тоже. Поэтому gap предсказуемее отступов.

Пять значений position

ЗначениеЗанимает место в потокеОтносительно чего смещается
staticдане смещается вовсе; top/left и z-index игнорируются
relativeда, староесвоего исходного места
absoluteнет, вынут из потокаближайшего позиционированного предка
fixedнетокна просмотра, не скроллится
stickyдаведёт себя как relative, пока не упрётся в заданный порог, дальше — как fixed внутри своего родителя

Ключевая пара — relative и absolute. Разница не в том, «на сколько сдвинулось», а в том, осталась ли дырка: relative уезжает визуально, но его прежнее место в потоке продолжает занимать соседей; absolute исчезает из потока, и соседи смыкаются.

«Ближайший позиционированный предок» — это ближайший предок с position, отличным от static. Если такого нет, отсчёт идёт от корневого блока страницы. Отсюда самый ходовой приём в CSS: родителю position: relative без единого смещения — только чтобы стать точкой отсчёта для абсолютного ребёнка.

Про sticky. Он не работает по двум причинам чаще всего: не задан порог (нужен хотя бы один из top/bottom/left/right) или у какого-то предка стоит overflow: hidden либо auto — тогда липкость ограничена этим контейнером и незаметна.

Порядок наложения: z-index работает не всегда

Первое правило: z-index действует только на позиционированные элементы — то есть на всё, кроме static. У position: static он не игнорируется частично, он игнорируется полностью. Исключение — флекс- и грид-элементы: им z-index работает и без позиционирования.

Когда z-index не задан, порядок всё равно есть, и он строгий: сначала фоны и рамки, затем блоки в потоке, затем плавающие, затем строчное содержимое, и только потом позиционированные элементы — среди них побеждает тот, что ниже в разметке.

Контекст наложения

Вот главное, ради чего этот раздел. z-index сравнивается только внутри одного контекста наложения (stacking context). Контекст — это как бы отдельный слой-аквариум: всё, что внутри, тасуется между собой, но целиком располагается там, где стоит сам аквариум.

<div class="A">   z-index: 1   ← создаёт контекст
   <div>          z-index: 9999
<div class="B">   z-index: 2

Кто сверху? B.
Ребёнок с 9999 соревнуется только внутри A,
а сам A проигрывает B со счётом 1 : 2.

Это и есть разгадка «поставила z-index: 9999, а модалка всё равно под шапкой»: элемент заперт в контексте предка. Увеличивать число бесполезно — надо либо поднимать сам контекст, либо выносить модалку в конец <body> (портал), где она попадёт в корневой контекст.

Контекст наложения создаёт:

  • корневой элемент <html>;
  • позиционированный элемент с z-index, отличным от auto;
  • position: fixed и sticky — всегда, даже без z-index;
  • opacity меньше 1;
  • transform, filter, perspective, clip-path, mask;
  • will-change с любым из этих свойств, isolation: isolate, contain: paint;
  • флекс- и грид-элемент с z-index, отличным от auto.
Самая коварная строчка. opacity: 0.99 визуально не меняет ничего — и создаёт контекст наложения. Ровно так же ведёт себя transform, поставленный «для анимации». Если выпадающий список внезапно уехал под соседний блок, ищи у предков opacity, transform или filter.

isolation: isolate — единственное свойство из списка, которое существует специально для этого: оно создаёт контекст и больше не делает ничего. Им намеренно запирают компонент, чтобы его внутренние z-index не воевали с остальной страницей.

Переполнение и новый контекст форматирования

overflow решает, что делать с содержимым, которое не влезло: visible (по умолчанию, торчит наружу), hidden (обрезано), scroll (полоса всегда), auto (полоса по необходимости), clip (обрезано без возможности прокрутки).

Побочный эффект важнее основного: любое значение, кроме visible, создаёт новый контекст форматирования блока (BFC). Внутри такого контейнера содержимое ведёт себя обособленно — в частности, контейнер начинает обнимать плавающие элементы и перестаёт схлопывать margin с детьми. Отсюда старый приём overflow: hidden у родителя, чтобы «он наконец увидел высоту детей».

Как чинить «не применилось» по порядку

  1. Блок шире, чем задано — считает content-box, добавь box-sizing: border-box.
  2. Промежуток меньше суммы отступов — схлопывание margin; во флексе и гриде используй gap.
  3. Абсолютный элемент улетел не туда — у нужного родителя нет position: relative.
  4. z-index не работает — проверь, что элемент позиционирован, и ищи чужой контекст наложения у предков.
  5. Родитель схлопнулся в ноль высоты — внутри только float; лечится display: flow-root или BFC.
