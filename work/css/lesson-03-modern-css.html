Современный CSS: Grid, каскадные слои и контейнерные запросы

Закрывает вопросы продвинутого теста про fr в Grid, @layer и @container — все отвечены наугад. За последние годы CSS обзавёлся тем, что раньше решали препроцессорами и JS: двумерной раскладкой, управлением каскадом и компонентами, которые сами подстраиваются под место.

CSS Grid: двумерная раскладка

Flexbox раскладывает элементы по одной оси, Grid — по двум сразу: строки и столбцы. Flex подходит для панели кнопок и ряда карточек, Grid — для каркаса страницы и сеток.

.layout {
  display: grid;
  grid-template-columns: 240px 1fr 2fr;
  gap: 16px;
}

Ключевая единица — fr (fraction, доля): доля свободного места в контейнере. Сначала вычитаются фиксированные размеры и зазоры, остаток делится пропорционально. В примере после колонки 240px оставшееся пространство разделится на три части: вторая колонка получит одну, третья — две.

Два приёма, заменяющих кучу медиазапросов:

grid-template-columns: repeat(auto-fill, minmax(200px, 1fr));

Столько столбцов шириной от 200px, сколько влезет, остаток растягивается. Карточки сами перестраиваются от телефона до монитора.

Совет. 1fr сам по себе означает minmax(auto, 1fr), и длинное слово или широкая картинка могут раздвинуть колонку. Если нужно жёстко держать пропорции, пишут minmax(0, 1fr).

Каскад и проблема специфичности

Урок про специфичность показал: побеждает селектор «тяжелее». В больших проектах это превращается в войну — чтобы перебить чужой стиль, добавляют селекторы, потом !important. Каскадные слои (@layer) вводят новый уровень приоритета, стоящий выше специфичности.

@layer reset, base, components, utilities;

@layer base       { a { color: blue; } }
@layer components { .card a { color: red; } }
@layer utilities  { .link { color: green; } }

Правило: стиль из более позднего слоя побеждает стиль из раннего независимо от специфичности. Порядок слоёв объявляют один раз — и .link (специфичность ниже) перебьёт .card a. Внутри одного слоя работает обычный каскад. Стили вне слоёв сильнее любых слоёв.

Практика: в слои складывают reset, стили библиотек и своей базы, чтобы сторонний CSS не выигрывал у вашего только потому, что у него громоздкий селектор.

Контейнерные запросы

Медиазапрос смотрит на размер окна. Но компонент вроде карточки живёт в разных местах: то в широкой основной колонке, то в узком сайдбаре, и ширина окна ничего о его месте не говорит. Контейнерный запрос (@container) реагирует на размер родительского контейнера.

.card-wrap { container-type: inline-size; }

.card { display: block; }

@container (min-width: 400px) {
  .card { display: grid; grid-template-columns: 120px 1fr; }
}

Теперь одна и та же карточка сама решает: в узком месте — столбиком, в широком — с картинкой слева. Компонент становится по-настоящему переиспользуемым, ему не нужно знать про страницу.

Ещё полезное

  • :has() — «родительский» селектор: .card:has(img) стилизует карточки, где есть картинка.
  • Вложенность — CSS теперь поддерживает & без препроцессора.
  • Пользовательские свойства (--color) живут в каскаде и меняются в рантайме, в отличие от переменных Sass.
  • clamp(min, ideal, max) — плавная адаптивная типографика без медиазапросов.
Что уносим с собой. Grid раскладывает по двум осям; fr — доля свободного места после фиксированных размеров и зазоров. @layer ставит приоритет выше специфичности: побеждает более поздний слой. @container реагирует на размер родителя, а не окна, и делает компоненты независимыми от страницы. :has(), вложенность и clamp() убирают часть препроцессоров и JS.
