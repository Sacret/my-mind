Доступность: семантика, клавиатура, ARIA

Доступность обычно представляют как «поддержку слепых» — редкий случай, до которого руки не доходят. На деле это про интерфейс, который не разваливается, если у человека нет мыши, экран увеличен вдвое, рука в гипсе или он читает страницу на солнце. Почти всё нужное даёт правильный HTML, а не специальные атрибуты.

Кому это нужно на самом деле

  • Клавиатура вместо мыши — не только незрячие: скорость, тремор, травма, неработающий тачпад.
  • Экранный диктор читает страницу вслух, ориентируясь на роли элементов и заголовки.
  • Увеличение — слабое зрение, мелкий шрифт: страницу масштабируют до 200% и она должна оставаться рабочей.
  • Цветовое зрение — примерно каждый двенадцатый мужчина не различает какие-то оттенки.
  • Временные ограничения — яркое солнце, шум в метро вместо звука, одна рука занята.

Семантика вместо div

Это главный раздел урока: правильный тег бесплатно даёт то, что иначе пришлось бы писать руками.

<div class="btn" onclick="save()">Сохранить</div>
<button onclick="save()">Сохранить</button>

У <button> из коробки есть: попадание в порядок табуляции, срабатывание по Enter и пробелу, роль «кнопка» для экранного диктора, состояние disabled, отправка формы. У div нет ничего — чтобы догнать, нужны tabindex="0", role="button", обработчики клавиш и обработка пробела отдельно от Enter.

Первое правило ARIA. Не использовать ARIA, если задачу решает обычный элемент. Атрибут role="button" на div сообщает диктору роль, но не добавляет ни фокуса, ни клавиатуры — получается кнопка, которая говорит, что она кнопка, но не работает как кнопка.

Доступное имя

У каждого интерактивного элемента должно быть имя, которое диктор произнесёт. Источники, по убыванию предпочтительности:

  • Видимый текст внутри кнопки или ссылки — лучший вариант.
  • <label for> для поля ввода: связка через id. Плейсхолдер меткой не является — он исчезает при вводе.
  • alt у картинки: описание смысла, а не «картинка». Для чисто декоративной — пустой alt="", чтобы диктор её пропустил.
  • aria-label — когда текста нет вовсе: кнопка-иконка «Закрыть», поле поиска без метки.

Ссылки «Подробнее», «Читать», «Сюда» — типичная беда: диктор умеет читать список всех ссылок страницы, и такой список превращается в двадцать одинаковых слов.

Клавиатура

  • Порядок табуляции — это порядок в DOM. Перестановка через CSS порядок не меняет, поэтому визуальный и клавиатурный обход могут разойтись.
  • Фокус должен быть видно. outline: none без замены — самая частая и самая тяжёлая ошибка: человек теряет позицию на странице. Свой стиль фокуса делают через :focus-visible.
  • Модальное окно забирает фокус внутрь, держит его там, закрывается по Esc и возвращает фокус на кнопку, которая его открыла.
  • Ловушки: элемент, из которого нельзя выйти по Tab, — блокирует всю страницу.
  • tabindex="0" — включить в обход; tabindex="-1" — фокус только из кода. Положительные значения ломают порядок и не нужны.
  • Ссылка «Перейти к содержимому» первой в документе избавляет от прохода через всё меню на каждой странице.

ARIA: состояния и динамика

Там, где нативного элемента нет, ARIA сообщает роль и состояние, которое меняется по ходу:

<button aria-expanded="false" aria-controls="menu">Меню</button>

<div aria-live="polite">Сохранено</div>    <!-- диктор прочтёт появившийся текст -->
<div aria-live="assertive">Ошибка сети</div> <!-- прервёт текущее чтение, для срочного -->

<span aria-hidden="true">★</span>          <!-- декоративный значок скрыт от диктора -->

aria-live решает специфическую для одностраничных приложений проблему: содержимое поменялось без перезагрузки, зрячий видит это сразу, а диктор молчит — потому что фокус никуда не переехал.

Важно: ARIA-атрибут не меняет поведение, он только сообщает. Значение aria-expanded обязано обновляться кодом вместе с реальным раскрытием, иначе диктор говорит неправду — а это хуже молчания.

Цвет, контраст, движение

  • Контраст по WCAG уровня AA: 4,5:1 для обычного текста и 3:1 для крупного текста и границ элементов управления. Светло-серая подпись на белом фоне — самое частое нарушение.
  • Не только цветом. Красная рамка у поля — не сообщение об ошибке; нужен текст, связанный с полем. Красная и зелёная линии на графике должны отличаться ещё и формой или подписью.
  • prefers-reduced-motion — системная настройка: при ней крупные движения и параллаксы отключают, они вызывают тошноту и головокружение.
  • Масштаб. Запрет зума в мета-теге viewport ломает страницу для слабовидящих; при 200% вёрстка должна оставаться пригодной.

Как проверять

  1. Убрать мышь. Пройти сценарий одной клавиатурой: всё ли достижимо, видно ли фокус, можно ли закрыть модалку.
  2. Автоматический аудит — axe, Lighthouse. Ловит контраст, отсутствующие метки и alt, но это лишь часть проблем: «кнопка называется Подробнее» машине не видна.
  3. Экранный диктор — VoiceOver на Mac, NVDA на Windows. Достаточно пройти главный сценарий вслух, чтобы услышать «кнопка, кнопка, кнопка» без имён.
  4. Масштаб 200% и чёрно-белый режим — быстрая проверка на цвет и вёрстку.

Экономический аргумент. Семантическая разметка даёт заодно понятный HTML, работающие формы, лучшую индексацию поисковиками и меньше кода: половина «доступности» — это отказ от самодельных виджетов там, где есть готовый элемент.

Что уносим с собой. Правильный тег бесплатно даёт роль, фокус и клавиатуру — ARIA нужна только там, где нативного элемента нет, и она сообщает, а не работает. У каждого элемента должно быть доступное имя; плейсхолдер — не метка. Порядок табуляции равен порядку DOM, фокус нельзя прятать, модалка возвращает фокус назад и закрывается по Esc. Контраст 4,5:1, ошибка не может быть выражена одним цветом, aria-live озвучивает изменения без перезагрузки. Проверка: клавиатура, axe, диктор, масштаб 200%.
