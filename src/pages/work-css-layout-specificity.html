Оси флексбокса и специфичность

Оба вопроса про CSS в тесте не сошлись: justify-content ты отнесла к поперечной оси, а самым специфичным селектором назвала тег. Это две главные причины фразы «почему-то не применилось» — и обе разбираются до состояния, когда угадывать больше не нужно.

Две оси, и обе зависят от direction

Флексбокс раскладывает элементы вдоль главной оси (main axis). Перпендикулярная ей — поперечная (cross axis). Какая из них горизонтальна, решает flex-direction:

flex-directionГлавная осьПоперечная ось
row (по умолчанию)горизонтально →вертикально ↓
columnвертикально ↓горизонтально →

Дальше запоминается одной строкой:

justify-content  →  вдоль ГЛАВНОЙ оси   (там, где элементы выстроены в ряд)
align-items      →  вдоль ПОПЕРЕЧНОЙ оси (перпендикулярно ряду)

Мнемоника: «justify» относится к тому же, к чему flex-direction. Задала направление — justify-content распределяет элементы именно по нему.

Отсюда следует то, на чём спотыкаются чаще всего: при flex-direction: column свойства меняются местами. Горизонтальное центрирование колонки делается через align-items: center, а не через justify-content.

/* ряд: по центру по горизонтали и вертикали */
display: flex;
justify-content: center;   /* по горизонтали */
align-items: center;       /* по вертикали   */

/* колонка: то же самое визуально, свойства поменялись ролями */
display: flex;
flex-direction: column;
justify-content: center;   /* теперь по ВЕРТИКАЛИ  */
align-items: center;       /* теперь по ГОРИЗОНТАЛИ */

Значения justify-content: flex-start, flex-end, center, space-between (края прижаты, промежутки равны), space-around (у каждого элемента равные поля, поэтому между соседями зазор вдвое больше, чем у краёв), space-evenly (все промежутки, включая крайние, одинаковы).

Значения align-items: stretch (по умолчанию — элементы растягиваются на всю поперечную ось), flex-start, flex-end, center, baseline (выравнивание по базовой линии текста, полезно для подписей разного кегля).

Мелочь, которая экономит время. align-content — не то же самое, что align-items. Он распределяет ряды между собой и работает, только когда включён перенос flex-wrap: wrap и рядов больше одного. Если он «не действует» — обычно как раз потому, что ряд один.

flex: три значения в одном свойстве

Сокращение flex раскрывается в три свойства:

flex: <grow> <shrink> <basis>;
flex: 1;        /* = flex: 1 1 0%   */
flex: auto;     /* = flex: 1 1 auto */
flex: none;     /* = flex: 0 0 auto */
  • flex-grow — как делить свободное место. Ноль означает «не расти».
  • flex-shrink — как сжиматься при нехватке места. Единица по умолчанию: элементы ужимаются сами.
  • flex-basis — размер до распределения, отправная точка.

Разница между flex: 1 и flex: auto тонкая, но заметная. При basis: 0 исходный размер содержимого не учитывается вовсе — элементы получаются равными. При basis: auto сначала берётся размер содержимого, а поровну делится только остаток — колонки выйдут разными.

flex-basis сильнее width: если заданы оба, вдоль главной оси побеждает flex-basis. width при этом не мусор — он остаётся точкой отсчёта при flex-basis: auto.

Классическая ловушка. Длинный текст или таблица растягивают флекс-элемент и ломают вёрстку, хотя стоит flex: 1. Причина: у флекс-элементов min-width по умолчанию равен auto, то есть «не меньше содержимого», и сжатие упирается в этот предел. Лечится min-width: 0 на элементе (для колонок — min-height: 0).

И маленькое, но приятное: промежутки между элементами задаются свойством gap, а не отступами у детей. Оно не добавляет лишнего поля с краёв и не требует правил вида :last-child { margin: 0 }.

Специфичность: три числа, а не одна сумма

Когда одно свойство задано несколькими правилами, побеждает более специфичный селектор. Специфичность считается как тройка (A, B, C):

РазрядЧто считаетсяПример
Aидентификаторы#header
Bклассы, атрибуты, псевдоклассы.btn, [type=text], :hover
Cтеги и псевдоэлементыdiv, ::before

Сравниваются разряды по очереди слева направо, и старший разряд решает всё — накопить его младшими нельзя:

#nav                        (1, 0, 0)
.menu .item .link:hover     (0, 4, 0)   ← четыре класса
div div div div div div     (0, 0, 6)

Побеждает #nav.

Это и есть ответ на вопрос из теста: тег — самый слабый разряд, идентификатор — самый сильный. Сотня тегов не перевесит один класс, а сотня классов — один #id. Считать нужно не «сколько всего», а «кто первым отличается».

Что специфичности не добавляет вовсе: *, комбинаторы >, +, ~ и псевдокласс :where() — у него специфичность всегда нулевая, поэтому он удобен в библиотечных стилях, которые должны легко перекрываться. У :is() и :not(), наоборот, специфичность равна самому сильному селектору внутри скобок.

Что происходит при равной специфичности

Побеждает то правило, которое идёт ниже по порядку. Отсюда практическое следствие: порядок подключения файлов важен, и правило «мой стиль не применился» часто означает не низкую специфичность, а то, что библиотека подключена после тебя.

Полный порядок разрешения

Специфичность — только третий шаг. Целиком браузер решает так:

  1. !important — отдельный, более приоритетный слой (у авторских стилей).
  2. Инлайновый style="" — сильнее любого селектора из таблиц стилей.
  3. Специфичность — та самая тройка.
  4. Порядок в исходнике — при полном равенстве.

Отдельно стоит понимать, что !important не «увеличивает специфичность», а выносит объявление в другой слой сравнения. Между двумя !important снова работают обычные правила. И само по себе это признак проблемы: почти всегда важное объявление появляется там, где проще было бы поправить порядок или селектор.

Каскад и наследование — разные механизмы

Каскад выбирает победителя среди правил, нацеленных на один и тот же элемент. Наследование — передача значения детям, когда для них правил нет вовсе.

Наследуются свойства текста: color, font-*, line-height, text-align, visibility. Не наследуются размеры, отступы, границы, фон, display. Поэтому font-family задают один раз на body, а padding — нет.

Как отлаживать быстрее. В инспекторе перечёркнутое свойство означает, что его перебило другое правило — и рядом видно какое. Если перечёркнутого нет, а эффекта тоже нет, дело не в каскаде: скорее всего свойство не действует на этот элемент (width у display: inline, align-content без переноса, z-index без позиционирования).
Что уносим с собой. justify-content — по главной оси, align-items — по поперечной, а какая из них горизонтальна, решает flex-direction. При column они меняются ролями. flex: 1 означает basis: 0 и равные колонки; сжатие ломается из-за min-width: auto. Специфичность — тройка (id, класс, тег), сравнивается поразрядно, и старший разряд младшими не набирается. При равенстве побеждает то, что ниже в коде.
