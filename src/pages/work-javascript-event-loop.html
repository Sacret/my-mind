Event loop: микрозадачи и макрозадачи

В тесте ты выбрал порядок «B C A» — то есть промис раньше синхронного console.log. Верный ответ «C B A». Разберём механизм, который это объясняет: он же отвечает за то, почему интерфейс иногда «замерзает».

Один поток и очередь дел

JavaScript в браузере выполняется в одном потоке. Это значит: в каждый момент времени выполняется ровно одна функция, и пока она не закончится, ничего другого не произойдёт — ни отрисовки, ни обработки клика.

Но при этом мы спокойно пишем таймеры и запросы к серверу, и страница не висит. Секрет в разделении обязанностей:

  • Стек вызовов — то, что выполняется прямо сейчас.
  • Браузерные API (таймеры, сеть, события) работают в стороне от JS и по готовности кладут колбэк в очередь.
  • Event loop — цикл, который берёт задачи из очередей и отдаёт их на выполнение, но только когда стек пуст.

Ключевая мысль. Никакой колбэк не может вклиниться в середину выполняющегося синхронного кода. Он ждёт, пока стек полностью опустеет.

Две очереди, а не одна

Очередей на самом деле две, и у них разный приоритет.

МикрозадачиМакрозадачи
.then / .catch / .finally, тело после await, queueMicrotask, MutationObserver setTimeout, setInterval, обработчики событий, сетевые колбэки, requestAnimationFrame (особый случай)

Алгоритм каждого «оборота» event loop:

  1. Выполнить весь синхронный код до конца — до полного опустошения стека.
  2. Выполнить все микрозадачи. Если микрозадача породила новую микрозадачу — её тоже, прямо сейчас, в этом же обороте.
  3. Отрисовать кадр, если пора.
  4. Взять одну макрозадачу и выполнить её. Вернуться к пункту 2.

Отсюда правило: синхронный код → все промисы → таймеры.

Разбор вопроса из теста

setTimeout(() => console.log('A'), 0);
Promise.resolve().then(() => console.log('B'));
console.log('C');

Пошагово:

  1. setTimeout вызывается — это обычный синхронный вызов. Он регистрирует колбэк в браузере и сразу возвращает управление. 'A' отправляется в очередь макрозадач.
  2. Promise.resolve().then(...) — промис уже выполнен, поэтому колбэк с 'B' сразу попадает в очередь микрозадач. Не выполняется, а именно ставится в очередь.
  3. console.log('C') — единственный синхронный вывод. Печатается C.
  4. Синхронный код кончился, стек пуст. Event loop разбирает микрозадачи → B.
  5. Микрозадач больше нет, берётся макрозадача → A.

Итог: C B A.

Откуда взялась ошибка. Легко подумать, что .then у уже выполненного промиса срабатывает мгновенно. Нет: колбэк промиса никогда не выполняется синхронно, даже если значение уже готово. Он всегда откладывается минимум до опустошения стека.

Почему setTimeout(fn, 0) — это не «сразу»

Ноль означает «положи в очередь макрозадач как можно скорее», а не «выполни немедленно». Реально колбэк дождётся: конца синхронного кода, всех микрозадач, возможно отрисовки кадра. Плюс браузер имеет минимальный порог около 4 мс для вложенных таймеров.

const t = Date.now();
setTimeout(() => console.log(Date.now() - t), 0);
for (let i = 0; i < 1e9; i++) {}   // считаем секунду
// выведет ~1000, а не 0

Тот же механизм объясняет зависший интерфейс: пока крутится тяжёлый синхронный цикл, стек не пуст, значит браузер не может ни отрисовать кадр, ни обработать клик. Лечится разбиением работы на куски через setTimeout или выносом в Web Worker.

async/await — это те же промисы

await — синтаксис поверх .then. Всё, что стоит после await, — это колбэк, попадающий в очередь микрозадач.

async function go() {
  console.log('1');
  await null;          // даже await над не-промисом ставит паузу
  console.log('3');    // это уже микрозадача
}
go();
console.log('2');
// 1, 2, 3

Тело async-функции выполняется синхронно до первого await. Дальше функция «отпускает» поток, и остаток кода планируется как микрозадача.

Одна ловушка про приоритеты

setTimeout(() => console.log('таймер'), 0);

Promise.resolve().then(() => {
  console.log('промис 1');
  Promise.resolve().then(() => console.log('промис 2'));
});

Вывод: промис 1, промис 2, таймер. Микрозадача, порождённая внутри другой микрозадачи, выполняется до перехода к макрозадачам — очередь микрозадач вычерпывается полностью. Из-за этого бесконечно самовоспроизводящиеся микрозадачи способны навсегда заблокировать отрисовку.

Что уносим с собой. Один поток. Колбэк ждёт опустошения стека. Промисы (микрозадачи) идут раньше таймеров (макрозадач) и вычерпываются полностью. await = точка выхода в микрозадачу. Тяжёлый синхронный код замораживает страницу целиком.
