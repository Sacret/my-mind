# my-mind

Личная программа обучения: общая эрудиция + профессия.

## Запуск

```sh
cd my-mind
npm start          # собрать страницы и поднять http://localhost:4173
npm run lan        # то же самое + доступ с телефона в той же Wi-Fi сети
npm run serve      # то же, но фоном: терминал можно закрыть, сервер останется
npm run stop       # погасить сервер, запущенный через npm run serve
```

`npm start` держит сервер, пока открыт терминал. `npm run serve` отвязывает его от терминала
(логи уходят в `/tmp/my-mind.log`), и он живёт до `npm run stop` или перезагрузки компьютера.
Другой порт — `PORT=8080 npm run serve`, гасится тогда так же: `PORT=8080 npm run stop`.

Зависимостей нет, `npm install` не нужен — и сервер, и сборщик написаны на встроенных модулях Node.

## Сборка страниц

Готовые HTML **собираются из источников** и правятся не напрямую:

```sh
npm run build      # собрать страницы из src/
npm run check      # ничего не писать, только проверить, что собранное актуально
```

- `src/layout.html` — общий каркас: `<head>`, подключение стилей, иконки. Описан **один раз**.
- `src/pages/*.html` — по файлу на страницу: блок параметров плюс разметка тела.
- На выходе — обычные статические HTML по прежним путям, так что двойной клик по файлу
  работает как раньше, без всякой сборки.

Блок параметров в начале источника:

| Параметр | Смысл |
|----------|-------|
| `title`  | заголовок вкладки |
| `out`    | куда собрать готовую страницу |
| `crumb`  | путь до страницы в липкой шапке, после `my-mind` |
| `body`   | класс на `<body>`, например `track-work` для синего акцента |
| `css`    | дополнительные стили помимо общего `lesson.css` |
| `js`     | общие скрипты из `assets/`, подставляются на место `{{scripts}}` |

Подстановки внутри разметки: `{{root}}` — путь к корню проекта, `{{crumb}}` — липкая шапка
с лого, ссылкой на оглавление и путём до страницы (ставится перед `.wrap`),
`{{scripts}}` — теги подключения скриптов.

### Стили

В HTML нет ни одного блока `<style>` и ни одного атрибута `style` — всё живёт в `assets/*.css`.

**Основа страницы задаётся только в `lesson.css` и одинакова везде:** `body` (кегль 17px/1.7),
`.wrap` (720px), `h1` (30px), `.lead`. Остальным таблицам переопределять эти правила нельзя —
иначе страницы начинают расходиться по ширине и размеру заголовков.

`lesson.css` подключается ко всем страницам и держит общее: палитру, типографику, кнопки,
карточки вопросов и переиспользуемые классы — `.panel` (поверхность карточки), `.status`,
`.tnum`, `.lead.sm` / `.lead.xs`, `.footnote`. Остальные таблицы добавляются параметром `css`
и содержат только то, что нужно одной странице.

**Править нужно `src/pages/`, а не собранные файлы** — в начале каждого готового HTML про это
стоит напоминание, и следующая сборка затрёт ручные правки.

**Зачем сервер.** Без него прогресс лежит в `localStorage` конкретного браузера: другой браузер
или очистка данных сайтов — и всё пусто. С сервером весь прогресс хранится в `data/state.json`
и не зависит от браузера.

Файлы можно по-прежнему открывать двойным кликом — тогда всё работает как раньше,
на `localStorage`. Дашборд показывает, в каком режиме он сейчас.

### Если прогресс, накопленный до сервера, не виден

`localStorage` разделён по источнику: данные, набранные при открытии файлов двойным кликом,
лежат под `file://`, а страницы с `http://localhost:4173` — это другой источник, и оттуда
старое хранилище не читается. Автоматически такое не переносится.

Перенос делает **`migrate.html`**: открой его именно двойным кликом из папки (не через localhost),
он покажет найденное в браузере и отправит на запущенный сервер. Ничего не удаляет и не затирает —
данные на сервере дополняются, а не заменяются.

### Отметка «угадала» и работа над ошибками

Под вариантами каждого вопроса стоит галочка **«не уверена, угадала»** — та же, что во входных
тестах. Смысл в том, что верный ответ наугад — такой же пробел, как ошибка, просто он не виден
в цифре результата.

- Отмеченный вопрос **не закрывает тему**: даже 8 из 8 остаётся жёлтым «!» в оглавлении,
  а рядом с результатом стоит «угадано N». Зелёная галочка появляется только за максимум
  без единой отметки — по этой же планке открываются уроки-продолжения.
- После проверки появляется кнопка **«Работа над ошибками»**: она оставляет на странице
  только провалы и угаданное и сбрасывает ответы именно на них. Остальные ответы целы,
  результат всё равно считается по всему уроку.
- Каждый такой вопрос **становится карточкой повторения** и уходит в нулевую коробку —
  ошибка возвращается сама, вручную ничего заводить не нужно.

В хранилище у урока лежит история попыток: `attempts` — дата, результат и номера провалов
каждой сдачи. Пересдача её не затирает, поэтому видно, что было провалено в первый раз
и сколько заходов ушло на максимум.

### Уроки-продолжения

Некоторые темы идут парами: второй урок опирается на первый и без него читается вхолостую.
Такой урок **закрыт, пока предыдущий не пройден на максимум** — на той же планке, по которой
в оглавлении ставится зелёная галочка.

Пока предыдущий не закрыт:

- в оглавлении строка не кликается: замок вместо галочки и подпись, чего именно не хватает;
- подсказка «Следующий шаг» такой урок пропускает — очередь до него ещё не дошла;
- открытая напрямую страница урока прячет и разбор, и вопросы, оставляя ссылку на предыдущий;
- карточки повторения по нему не появляются — они и так ждут прохождения своего урока.

Задаётся это одной строкой в реестре `assets/lessons.js`:

```js
{ track: "work", id: "work-react-effects-memo", …, needs: "work-react-state-context" }
```

`assets/lessons.js` — общий список уроков для оглавления, карточек и самих страниц:
порядок, ссылки, число вопросов и зависимости. Новый урок добавляется туда одной записью.

## Повторение карточками

`review/index.html` — интервальные повторения по уже пройденным темам: 613 написанных карточек
на все 75 уроков плюс те, что добавляются сами из промахов. Открыто 567 — остальные 46 ждут,
пока будут пройдены их уроки.

- Карточка открывается только после прохождения соответствующего урока.
- Кроме рукописных карточек из `review/cards.js` в колоде есть **сделанные из промахов**:
  вопрос, проваленный или отмеченный «угадала», сам становится карточкой (лицо — вопрос,
  оборот — верный ответ) и стартует с нулевой коробки. Объяснение из урока едет отдельным
  полем `note` и показывается сноской под ответом: вспоминать надо ответ, а не объяснение. Такая карточка помечена
  «ошибка в уроке» или «угадано в уроке»; повторный промах по тому же вопросу не плодит дубли,
  а просто возвращает её в начало. Живут они в хранилище под ключом `cards:auto`.
- Три оценки: «Легко» перепрыгивает через коробку, «С трудом» двигает на одну,
  «Не вспомнила» обнуляет коробку и возвращает карточку в конец текущей сессии.
- Интервалы по коробкам: 1 → 3 → 7 → 16 → 35 дней, с разбросом ±15%,
  чтобы карточки одного урока не возвращались одним комком.
- Дневные лимиты (меняются внизу страницы карточек): по умолчанию **10 новых** и **40 всего**.
  Просроченные показываются раньше новых — долг важнее притока.
- Нагрузка сама выходит на плато: закреплённая карточка возвращается раз в 35 дней.
  На симуляции 60 дней при 36 открытых карточках выходит пик 20 в день на старте
  и 0–4 в день в устоявшемся режиме. Без лимитов первый день дал бы 36, четвёртый — 27.
  Это расчёт; что происходит на самом деле, показывает блок «Как идут повторения» в оглавлении.
- Управление с клавиатуры: пробел показывает ответ, `1` / `2` / `3` — оценки.
- Кнопка «Выгрузить в Anki (CSV)» отдаёт колоду в формате `вопрос;ответ;тег`,
  если захочется повторять с телефона.

Порядок дня: сначала карточки (3–5 минут), потом новый урок.

### Как идут повторения

Внизу оглавления — три среза по фактам из хранилища, а не по симуляции:

- **По коробкам** — где сейчас лежат открытые карточки. Перекос влево означает, что материал
  не держится; здоровая картина — горка, сползающая в дальние коробки.
- **Созреет в ближайшие 7 дней** — сколько карточек выйдет из интервала по дням. Столбец
  «сегодня» включает всё просроченное, а дневной потолок может растянуть пик на пару дней.
- **Доля «не вспомнила»** — сколько оценок из всех за две недели пришлось на провал.
  Ориентир: выше 20% — интервалы великоваты и стоит убавить приток новых карточек,
  ниже 5% — можно добавить.

Считается это в `assets/srs.js` (`SRS.stats`), рисуется в оглавлении. Данные берутся из двух мест:
у каждой карточки в `srs:v1` копятся `seen` (сколько раз спрашивали), `lapses` (в скольких
разных сессиях не вспомнилась) и `streak` (сколько успехов подряд после последнего провала),
а `srs:log` держит по дням, сколько было оценок и провалов, за последние 60 дней. Оба счётчика начинают заполняться с первой сессии после обновления — по прошлым
повторениям данных нет.

### Залипшие карточки

Карточка, которая **трижды забылась в разные дни**, выносится в оглавлении отдельным
блоком со ссылкой на её урок. Смысл в том, что это не «покажи ещё раз», а сигнал, что тема
не понята: разбирать такое надо через урок, а не через повторение. Порог — `SRS.LEECH`.

Считаются именно разные сессии. «Не вспомнила» возвращает карточку в конец текущей сессии,
и раньше каждый такой заход шёл в `lapses` — один плохой вечер сам набирал порог. Теперь
повтор в той же сессии в счётчик не идёт (флаг `repeat` в `SRS.applyGrade`).

Выйти из списка тоже можно: метка снимается, когда после последнего провала карточка
вспомнится `SRS.LEECH_CLEAR` раз подряд (сейчас — два). Успех переводит карточку минимум
в первую коробку, поэтому эти два раза всегда приходятся на разные дни.

Типовые причины залипания, если карточка не выходит из списка сама:

| Причина | Как выглядит | Что делать |
|---|---|---|
| Интерференция | две карточки урока об одном и том же с разных сторон | слить в одну |
| Перегруз | в ответе список из трёх-четырёх пунктов | разрезать на карточки |
| Фронт-заголовок | лицо называет тему, а не задаёт вопрос | переписать вопросом с определённым ответом |
| Голый факт | нечего вывести, только вспомнить | добавить в ответ зацепку — связь или мнемонику |

При разрезании карточке нужен **новый id**: `srs:v1` привязан к id, и старая история
(коробка, провалы) осталась бы висеть на другом содержимом. Запись снятого id из `srs:v1`
надо удалить руками.

## Как работать

1. Открыть `index.html` — там видно, сколько карточек ждёт, что пройдено и что делать дальше.
2. Прочитать урок, ответить на вопросы, отметив галочкой те, где ответ угадан, нажать «Проверить».
3. Если есть промахи или отметки — перечитать разделы по ним и нажать «Работа над ошибками»:
   заново спросят только эти вопросы. Они же вернутся карточками в повторение.
4. Когда захочется новую партию уроков — просто сказать Claude. Выгружать ничего не нужно:
   весь прогресс лежит в `data/state.json`, он читает его сам.

Кнопки «Сохранить прогресс в файл» на дашборде и «Сохранить отчёт в файл» в тестах никуда
не делись, но теперь они нужны не для отчётности, а если хочется читаемой копии или архива
конкретной попытки.

## Занятия с других устройств

`data/state.json` — единственный файл, в котором живёт весь прогресс. Отсюда варианты:

| Что нужно | Как |
|-----------|-----|
| Другой браузер на этом компьютере | Уже работает: запусти сервер, открой `localhost:4173` |
| Телефон или планшет дома | `npm run lan`, открыть показанный адрес вида `http://192.168.x.x:4173` |
| Другой компьютер | Держать папку `my-mind` в синхронизируемой директории (iCloud Drive, Dropbox, Яндекс.Диск) — `state.json` уедет вместе с ней. На втором компьютере так же запускается `npm start` |
| Разовый перенос куда угодно | На оглавлении «Выгрузить прогресс в файл», в другом браузере — «Загрузить из файла» |

Оговорка про синхронизацию: не занимайся одновременно на двух машинах, пока папка не досинхронизировалась —
победит то состояние, которое сохранится последним. Страховка на этот случай — ежедневные копии
в `data/backups/`.

Режим `--lan` открывает доступ всем в сети без пароля. Дома это нормально, в кафе или коворкинге — нет.

## Публичная копия на GitHub Pages

Сайт публикуется воркфлоу `.github/workflows/pages.yml` при каждом пуше в `master`.
В артефакт попадают только собранные страницы и `assets/`; `data/`, `src/`, `server.mjs`
и `migrate.html` исключены, так что мой прогресс на сайт не уезжает — он остаётся
в репозитории и на этой машине.

Посетителю страницы отдаются как есть. `assets/storage.js` ходит за `/api/state`
только с localhost или домашнего адреса вида `192.168.x.x`; на чужом хосте он сразу
работает с `localStorage`, поэтому у каждого свой прогресс и видит его только он сам.
Ничего никуда не отправляется — бэкенда у публичной копии нет.

Прогресс переносится файлом: на оглавлении есть «Выгрузить прогресс в файл»
(скачивается `my-mind-ГГГГ-ММ-ДД.json`) и «Загрузить из файла» — с выбором,
заменить нынешний прогресс целиком или добавить к нему. Те же кнопки работают
и локально: это ручная резервная копия в дополнение к `data/backups/`.

Чтобы публикация включилась: в настройках репозитория **Settings → Pages → Build and
deployment → Source** выбрать **GitHub Actions**. Если репозиторий приватный, Pages
на бесплатном тарифе не публикуются.

## Пересдача входных тестов

Ответы теста лежат в `quiz:<test-id>` и при пересдаче перезаписываются — прежние варианты
не сохраняются. А вот **результат** каждой проверки дописывается в отдельный ключ
`quiz:<test-id>:attempts` и не теряется: кнопка «Сбросить» стирает только ответы.

Одна запись — дата, балл, номера промахов, номера «угадала» и разбивка по категориям.
Итог сохраняется готовым, а не пересчитывается потом из ответов: вопросы правятся,
и старая попытка иначе меняла бы балл задним числом.

Что из этого видно:

- на странице теста сверху — таблица «Попытки»: когда, сколько, изменение к прошлому разу;
- после проверки — сравнение с предыдущей попыткой по категориям и списки
  «стало верно» / «разучилось» с номерами вопросов;
- в оглавлении, блок «Тесты», — те же строки по каждому тесту и сдвиг от первой попытки.

Повторная проверка тех же ответов в тот же день новой попыткой не считается.
Логика общая для тестов и оглавления — `assets/attempts.js`.
